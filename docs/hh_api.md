# HH.ru — официальный API (изучено по первоисточнику)

Проверено по [OpenAPI HH](https://api.hh.ru/openapi/redoc) и [github.com/hhru/api](https://github.com/hhru/api),
июнь 2026. Ключевые факты — с эмпирической проверкой.

## Главное: легальный путь жив

Ранее по вторичным источникам считалось, что «API HH для соискателей закрыт». **Первоисточник
показывает иное:**

- `https://dev.hh.ru` — **работает (HTTP 200)**, регистрация приложений открыта.
- Официальный README HH: зарегистрируй приложение на dev.hh.ru → настрой OAuth2.
- Эндпоинт `POST https://api.hh.ru/token` — **жив** (проверено: с фейковыми ключами отдаёт
  корректную ошибку `invalid_client`, а не блок).
- Поиск `GET /vacancies` (`operation: get-vacancies`) — рабочий; в доке прямо: *«если не передан
  токен авторизации, после первого запроса будет предложено пройти капчу»*. То есть **с токеном
  поиск работает** (мой прежний `403` был из-за анонимного запроса с дата-центрового IP).

Вывод: **HH подключаем через своё официальное приложение (OAuth2), без эмуляции и обхода.**

## Три типа токена (OAuth2)

| Grant | Что даёт | Нужен логин Павла? | Для чего |
|-------|----------|--------------------|----------|
| `client_credentials` | токен **приложения** | нет | поиск вакансий (`GET /vacancies`) |
| `authorization_code` | токен **соискателя** | да (один раз) | персональный поиск, **отклики** (`/negotiations`), резюме (`/resumes/mine`) |
| `refresh_token` | обновление токена соискателя | нет | продление без повторного логина |

Заголовок `HH-User-Agent: AppName/1.0 (email)` обязателен во всех запросах.

## Настройка

### 1. Зарегистрировать приложение
[https://dev.hh.ru/admin](https://dev.hh.ru/admin) → создать приложение → получить
`client_id` и `client_secret`. Указать `redirect_uri` (любой адрес, на который HH вернёт `code`,
например `https://example.com/oauth` — достаточно скопировать `code` из адресной строки).

В `.env` (на сервере, не в git):
```
HH_CLIENT_ID=...
HH_CLIENT_SECRET=...
HH_REDIRECT_URI=https://example.com/oauth
HH_USER_AGENT=findwork/1.0 (sunpavel@gmail.com)
```

### 2. Поиск вакансий (токен приложения, без логина)
Ничего больше не нужно — `src/sources.py` сам получит токен приложения по
`client_credentials` и закэширует его:
```
python3 src/pipeline.py --source hh --dry-run
```

### 3. Отклики и персональный поиск (токен соискателя, один раз)
```
python3 src/hh_auth.py url            # открой ссылку, авторизуйся, скопируй code из адреса
python3 src/hh_auth.py code <CODE>    # сохранит state/hh_token.json
python3 src/hh_auth.py refresh         # позже — продлить
```
После этого пайплайн использует персональный токен (он в приоритете над токеном приложения),
а на Фазе 2 станут доступны отклики через `POST /negotiations`.

## Полезные эндпоинты (из спецификации)

| Метод | Назначение |
|-------|-----------|
| `POST /token` | получение/обновление токена |
| `GET /vacancies` | поиск вакансий (params: `text`, `area`, `experience`, `salary`, `per_page`, `page`…) |
| `GET /vacancies/{id}` | полное описание вакансии |
| `GET /me` | профиль авторизованного пользователя |
| `GET /resumes/mine` | резюме соискателя |
| `POST /negotiations` | отклик на вакансию (резюме + сопроводительное) |

Ограничения поиска: глубина выдачи ≤ 2000 (`per_page`×`page`), `per_page` ≤ 100.

## Замечания по эксплуатации
- Запуск с дата-центрового IP (VPS) — с валидным токеном ок; анонимные запросы оттуда HH режет.
- Соблюдать вежливые лимиты и паузы; отклики — только после подтверждения (наш режим).
- `area=1` — Москва; формат «неважно» → можно расширить регионы/удалёнку позже.
