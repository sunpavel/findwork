# Отклик под выбранную вакансию (Фаза 2)

> Реализует твой сценарий:
> - **HH.ru** — присылаешь боту ссылку на вакансию → он создаёт релевантное резюме
>   на основе твоих резюме, пишет сопроводительное, показывает их и **спрашивает
>   подтверждение** кнопкой «✅ Откликнуться». Отклик уходит только после твоего нажатия.
> - **facancy.ru (и другие сайты)** — бот достаёт текст вакансии, генерит резюме и
>   сопроводительное и **присылает их тебе**; отклик ты делаешь сам на сайте.
>
> Ты наблюдаешь и в любой момент можешь поставить на паузу (`/pause`).

## ⚠️ Важно про риск (прочитай)

Создание/правка резюме и отклики **заблокированы в официальном dev-API HH** (мы
проверили — 403). Доступ к ним даёт только токен **официального мобильного
приложения HH**, под которое мы и работаем (как `hh-applicant-tool`).

Это **«серый» путь**: формально нарушает ToS HH и несёт **риск блокировки твоего
аккаунта** (касается только HH-откликов; facancy-режим ничего на HH не делает).
Чтобы снизить риск, в коде уже есть:

- **подтверждение** — отклик на HH уходит только после нажатия кнопки (по умолчанию);
- **пауза** (`/pause`) — мгновенно останавливает отклики;
- **дневной лимит** (`APPLY_DAILY_LIMIT`, по умолчанию 30);
- **пауза перед действием** (`APPLY_PAUSE_SEC`) — имитация человека;
- **анти-дубль** — на одну вакансию не откликаемся дважды;
- **точечность** — отклик идёт только на вакансию, которую *ты прислал*, а не массово.

## Как это работает (поток)

### HH.ru — с подтверждением
```
ты присылаешь боту ссылку на вакансию hh.ru
        │
        ▼  apply.prepare(...)
  hh_app.get_vacancy → relevance.score_vacancy → tailor.tailor
        │                (читаем вакансию, скорим, готовим резюме + письмо)
        ▼
  бот показывает резюме и письмо + кнопки [✅ Откликнуться] [✖️ Отмена]
        │
        ▼  (ты жмёшь «Откликнуться») → apply.commit(...)
  hh_app.clone_resume(base, …)  →  hh_app.apply_to_vacancy(…)
        │   резюме под вакансию          отклик: резюме + письмо
        ▼
  лог в state/applications.jsonl + учёт дневного лимита
```

### facancy.ru и другие сайты — ассистент (без отправки)
```
ссылка facancy.ru → webvac.fetch_vacancy → tailor.tailor → бот присылает тебе
                    (текст со страницы)    (резюме+письмо)   (отклик делаешь сам)
```

Модули: `src/hh_app.py` (клиент эмуляции HH), `src/webvac.py` (фетчер прочих сайтов),
`src/tailor.py` (адаптация), `src/apply.py` (prepare/commit), `src/bot.py` (Telegram).

## Настройка

### 1. Авторизация под приложение HH (один раз)

Проще всего — зрелым инструментом `hh-applicant-tool` (он реализует OAuth
официального приложения и хранит токен, который мы переиспользуем):

```bash
pipx install hh-applicant-tool        # или: pip install hh-applicant-tool
hh-applicant-tool authorize           # откроет браузер, авторизуешься своим HH-аккаунтом
```

После этого токен лежит в `~/.config/hh-applicant-tool/` и `src/hh_app.py` подхватит
его автоматически. Проверка:

```bash
python3 src/hh_app.py                  # покажет имя соискателя и список резюме
python3 src/hh_app.py https://hh.ru/vacancy/12345678   # + прочитает вакансию
```

Альтернатива: положить токен в `HH_APP_ACCESS_TOKEN` (см. `.env.example`).

### 2. Ключ Claude (опционально, для качества текста)

```bash
pip install -r requirements.txt        # ставит anthropic
export ANTHROPIC_API_KEY=sk-ant-...     # в .env, не в репозиторий
```

Без ключа всё работает, но письма/«о себе» генерит шаблон (проще по тексту).
Модель по умолчанию — `claude-opus-4-8` (можно сменить через `ANTHROPIC_MODEL`).

### 3. Базовое резюме и режим

- `HH_BASE_RESUME_ID` — на основе какого резюме адаптировать (если не задано, берётся
  первое из твоих). Список id — командой `python3 src/hh_app.py`.
- `APPLY_RESUME_MODE`:
  - `clone` *(по умолчанию, как ты просил)* — **новое** резюме под каждую вакансию;
  - `update` — правим **базовое** резюме под вакансию (не плодим резюме, безопаснее);
  - `existing` — откликаемся базовым резюме как есть (адаптируем только письмо).

## Запуск

### Разовый отклик из консоли

```bash
python3 src/apply.py https://hh.ru/vacancy/12345678            # отклик
python3 src/apply.py https://hh.ru/vacancy/12345678 --dry-run  # показать письмо/скор, не отправляя
python3 src/apply.py --status            # пауза, лимит, режим
python3 src/apply.py --pause             # пауза
python3 src/apply.py --resume            # снять паузу
```

### Бот (основной режим)

```bash
TG_BOT_TOKEN=... TG_CHAT_ID=... python3 src/bot.py
```

Дальше шлёшь боту ссылки на вакансии:
- ссылка **HH** → бот покажет резюме и письмо и кнопку «✅ Откликнуться» (отклик — после нажатия);
- ссылка **facancy.ru** (или другого сайта) → бот пришлёт резюме и письмо, отклик делаешь сам.

Команды: `/health` (что подключено: Telegram/Anthropic/HH), `/status`, `/pause`, `/resume`, `/dry <ссылка>`, `/help`.

> CLI `python3 src/apply.py <url>` откликается на HH-вакансию **сразу, без кнопки** —
> это для «прямого» режима; основной путь (бот) — с подтверждением.

### Автозапуск на VPS (systemd)

`/etc/systemd/system/findwork-bot.service`:

```ini
[Unit]
Description=findwork Telegram bot (auto-apply)
After=network-online.target

[Service]
WorkingDirectory=/opt/findwork
EnvironmentFile=/opt/findwork/.env
ExecStart=/usr/bin/python3 /opt/findwork/src/bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now findwork-bot
journalctl -u findwork-bot -f
```

## Что в логе

`state/applications.jsonl` — по строке на действие: вакансия, компания, скор,
id резюме, чем сгенерён текст (`llm`/`template`), режим, время. Используется и для
дневного лимита, и для анти-дубля. Каталог `state/` — в `.gitignore`.

## Если что-то пошло не так

- `403` на резюме/откликах с dev-токеном — это ожидаемо; авто-отклик идёт **только**
  через токен приложения (п. 1), не через `HH_CLIENT_ID/SECRET`.
- `403/блокировка` на токене приложения — возможен бан/ограничение аккаунта: останови
  бота (`/pause`), снизь лимит, сделай паузу на день.
- Нет резюме у соискателя — создай хотя бы одно резюме на hh.ru вручную (база для адаптации).
